Platforms · Portability

MNP Platform

The national number-portability switching backbone — the authoritative record of every ported number in Bangladesh, operated as a neutral clearing house under BTRC mandate.

What is MNP

One mechanism, understood two ways.

For subscribers

Keep your number. Change your network.

Mobile Number Portability means you can leave your current mobile operator and join a new one without changing your phone number. Your number, your contacts, and the way people reach you stay exactly the same — only the network behind the number changes.

For the ecosystem

Decoupling the MSISDN from the serving network.

MNP is a regulatory mechanism that decouples the MSISDN from the network that serves it, enabling subscriber migration across operators while preserving routing integrity. The Central Number Portability Database maintains the authoritative mapping, so every call and message resolves to the subscriber's current network.

Architecture

How a number ports across the network.

A porting request moves through the clearing house, updates the national database, and is broadcast to every operator — so routing stays correct the moment the port completes.

Origin Subscriber Requests to switch operator
Donor Current MNO Releases the number
Infozillion NPCH → CNPDB Validates, orchestrates, records
Recipient New MNO Activates the number
Broadcast → The completed port is published from the CNPDB to all connected operators, so every network routes calls and messages to the new serving operator.
NPCH

Number Portability Clearing House

The central coordination engine for every porting request in the country. The NPCH receives, validates, and orchestrates the switching workflow between the donor and recipient operators.

01
Request submission

The recipient operator submits the porting request on the subscriber's behalf, with the identity details required by regulation.

02
Identity validation

The request is validated against subscriber and eligibility criteria before any network change is initiated.

03
Donor release

The current (donor) operator confirms release of the number within the regulated workflow.

04
Recipient activation

The new (recipient) operator activates service on the ported number.

05
CNPDB update

The central database is updated and the change is broadcast to all operators, completing the port.

CNPDB

Central Number Portability Database

The CNPDB is the authoritative national record of every ported number in Bangladesh. Upon successful porting, the database is updated and the change is broadcast to all connected operators to ensure calls and messages route to the correct network.

It is the single source of truth the entire ecosystem depends on — the reference against which every routing decision for a ported number is resolved.

Key point

All four mobile network operators query this database in real time to route calls and messages accurately.

Lookup Service

Identifying the current serving network.

The lookup service identifies the current serving network of any mobile number — the operational answer to "which operator hosts this number right now?" after any porting history is accounted for.

  • Routing accuracy for calls and messages
  • Fraud prevention and number validation
  • Identification of ported numbers
  • Detection of disconnected or non-mobile numbers
Also known as

MNP dipping — the query-and-response lookup that keeps high-volume calls and enterprise messaging reaching the right network.

Platforms · Messaging

A2P SMS Platform

The mandatory national layer through which all enterprise-to-subscriber SMS traffic in Bangladesh is validated, corrected, and mediated — connecting licensed aggregators downstream to operators upstream.

Platform role

Not a messaging service. A national control layer.

Infozillion operates the Central A2P SMS Platform — the mandatory validation and mediation layer through which all enterprise-to-subscriber SMS traffic in the country is processed. It governs who may send, what may be sent, and how each message reaches the subscriber's correct network.

Every licensed A2P SMS aggregator connects to the platform downstream. The platform validates each submission, applies MNP port correction, enforces regulatory controls, and hands the message off to the correct upstream network — the mobile operator (MNO) or IPTSP that currently serves the recipient.

This central position is what makes national governance possible: a single point where sender identity, content, and routing are checked before any message reaches a subscriber.

Two-sided platform

Downstream: licensed aggregators submit traffic. Upstream: MNOs and IPTSPs (ANS) receive validated, correctly-routed messages.

Traffic flow

How an enterprise message reaches a subscriber.

Each message passes through submission, validation, CLI and content checks, MNP port correction, and delivery to the correct serving network.

Origin Enterprise Client Bank, brand, or service
Downstream Licensed Aggregator Submits to the platform
Infozillion Central Platform Validate · CLI · DND · port correct
Upstream · ANS MNO / IPTSP Delivers to subscriber
MNP port correction → Before handoff, the platform resolves the recipient's current serving network, so a message addressed to a ported number still reaches the right operator.
Validation & CLI governance

Checking who is sending, and correcting where it goes.

Every submission is validated before it moves upstream. The platform checks the registered Sender ID and CLI masking, verifies aggregator credentials, and confirms the message conforms to registered templates. Port correction then ensures the message routes to the subscriber's current network.

  • Sender ID / CLI masking registration
  • Aggregator credential verification
  • Registered template conformance
  • MNP port correction on every message
Why it matters

Validation prevents spoofing, brand impersonation, and unauthorised Sender IDs from ever reaching a subscriber — protecting enterprises and the public alike.

DND enforcement

Respecting the Do Not Disturb registry.

Do Not Disturb (DND) is a subscriber's registered preference not to receive promotional messaging. The platform enforces DND registry compliance before a message is routed — promotional traffic addressed to a DND-registered subscriber is stopped at the central layer, not left to individual senders to honour.

Subscriber protection

Enforcing DND centrally means the protection is uniform across every aggregator and operator — a single, consistent line of defence for subscribers.

Content & template compliance

What is sent is what was approved.

Enterprise messaging operates against a framework of registered templates. The platform checks message content against the approved template for each sender, so what reaches subscribers matches what was registered and permitted under BTRC regulation.

This protects enterprise clients — their brand and their approved messaging — as much as it protects subscribers from unregistered or manipulated content.

Equal protection

Template compliance safeguards the enterprise's brand integrity and the subscriber's trust in a single check.

Compliance & Regulation

BTRC framework

Operating under regulatory mandate.

The Bangladesh Telecommunication Regulatory Commission (BTRC) is the national telecom regulator. Infozillion operates its Mobile Number Portability platform and Central A2P SMS Platform under BTRC license and directive.

Compliance is operational, not incidental: the mandate defines what each platform does, how traffic is validated, and what records are kept — for both portability and enterprise messaging.

Regulator

Licensed MNPSP and Central A2P SMS Platform operator, governed by BTRC directive.

Audit model

Built to be auditable.

The platform is subject to regulatory audit. Its internal posture supports this directly: transactions are logged, and activity is traceable across the porting and messaging workflows.

Posture

Transaction logging and traceability mean the platform can answer to audit — the message is simple: it is auditable.

CLI / DND policy

Registered senders, protected subscribers.

A2P senders must register their CLI / Sender ID before traffic is accepted. DND enforcement protects subscribers who have registered a Do Not Disturb preference, applied centrally before any promotional message is routed.

Both policies derive from BTRC directive and are enforced at the platform layer, uniformly across every aggregator and operator.

Uniform enforcement

Applied centrally, so CLI and DND protection is consistent across the entire ecosystem.

Data protection

A clear posture on data.

The platform handles transaction and subscriber data as part of its function. Data is retained for operational and audit purposes, logged for traceability, and not shared beyond what the platform's regulated role requires.

Principle

Retain what the mandate requires, log for audit, share nothing beyond the regulated function.

FAQ · Ecosystem

Partner & integration questions.

For aggregators, operators, and IPTSPs. Consumer porting questions live in the Consumer Guide.

Onboarding follows BTRC-aligned procedures. A valid aggregator license, CLI/Sender ID registration, and registered template compliance are required before credentials are issued and integration begins. IP activation requires a Bangladesh-based IP address per BTRC guideline.
Aggregators connect through a documented API for submission, delivery reports, and balance and CLI checks. Full technical documentation is provided to licensed aggregators through the Central Platform portal, not published publicly.
There is no TPS limit on the core APIs, including Send-SMS. The one exception is the delivery-report (DLR) check API, which is limited to 20 calls per second; exceeding it returns an HTTP 429.
Every sender must register its CLI / Sender ID, activated at the MNO and synced to the Central Platform. The platform validates registration on each submission, preventing spoofing and unauthorised sender identities from reaching subscribers.
Content approval requests are processed within 30 minutes. Approved content must be used exactly as registered — any change, including spaces or punctuation, will fail content validation.
DND enforcement is applied centrally, before routing. Promotional traffic to DND-registered subscribers is stopped at the platform layer, uniformly across all aggregators.
The platform resolves each recipient's current serving network before handoff, so messages to ported numbers reach the correct operator without action on the aggregator's part. This is why a message to a recently ported number still delivers correctly.
Charging applies when the platform successfully processes a Send-SMS call and receives a successful response from the ANS — platform response code 9000 and ANS response code 1000.
Escalation is role-based across three tiers — NOC Engineer, Service Assurance, and Operations Head — so partners reach the right level of response regardless of individual availability. Support is available 24/7/365.
